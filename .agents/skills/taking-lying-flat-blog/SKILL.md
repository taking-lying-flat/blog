# 博客论文笔记维护

维护本仓库时采用下列已确认惯例。用户本次明确要求优先；不要把一次局部修改扩大成整站重写。

## 论文博客的段落结构

- **总起句不能太短**：每组说明前，用完整、信息充分的总起句概括主题、关键机制或结论，并带出下面的解释。不能只写几个字的标签、重复小标题，或为了压行删掉必要上下文。通常一至两句即可，不靠空话凑长度。
- 总起句沿用论文博客的顶格加粗样式；下面的解释使用真正的无序列表缩进。同层说明保持同一缩进，换行对齐列表正文，不堆空格、全角空格或连续 `<br>`。
- 公式、算法和图片按各自容器排版，不因为前面是列表就额外嵌套、逐行加项目符号或产生双重缩进。合并说明时同步处理列表边界，不能留下空项目。
- **对齐现有论文博客风格**：优先以同系列已完成文章为参照；生成模型内容以生成模型系列为基准。一起核对总起句、列表层次、标题、说明框、数学字体、公式编号和图文间距，不只对齐某一项，不临时另造样式。

## 公式与算法

- **保留原式**：忠实于用户文档或论文。排版任务不改变量、不添加辅助记号、不改写为另一个等价表达式，也不自行调整求和范围或算法步骤。发现疑似数学错误时先指出具体差异，区分排版修复与内容修正。
- **能单行放下就单行**：以实际桌面正文宽度判断，不能仅因公式代码长就换行。只在用户指定或实际溢出时分行，不靠缩小全部数学字体解决排版。
- **公式编号必须完整、连续、对应正确**：新导入或改动范围内的独立展示公式沿用该论文的编号序列，按阅读顺序检查漏号、跳号和重号；一篇文章包含多篇论文时，各篇独立编号。编号位于正文右侧，不挤进公式、不超出正文边界。
- 同一个多行公式只用一个编号，编号与公式整体对齐。插入、删除或移动公式后，同步核对“式（n）”等正文引用及锚点；补充推导接入时也要与正文编号衔接。不要同时使用两种机制给同一公式重复编号。
- 保留行内公式的行内形态，不给行内符号补展示编号。上下标、括号和用户指定的行数逐项核对；不能把算法步骤编号混入正文公式编号。
- **算法截图默认转为 LaTeX**：导入新内容或维护用户指出的算法时，核对原图/PDF，保留 Input/Require、循环、条件、返回值、下标、缓存更新和原步骤顺序。使用现有论文式算法容器及 MathJax，不能把算法继续当作成品位图交付。
- 算法标题和正文公式编号分开。算法内文字通常为英语，沿用原论文术语。可以按现有样式添加行号，但不借排版改变逻辑。
- 原截图留在归档资源中，页面由 LaTeX 版本替代，避免重复显示。图片中的普通实验图表不因这条规则自动改写为算法。

## 文字与图片

- **全站正文行距为 1.82**：复用 `site/reader.css` 的 `--article-line-height`，包括列表、说明框、表格文字和算法说明；不再添加逐篇正文行距覆盖。标题、代码块和数学数组有各自的排版规则。
- 补充推导沿用生成模型系列的浅色框、完整总起句和无序列表。用户要求合并或上移时，处理段落结构，不用随意的负边距掩盖。
- 图片居中、保持原始比例，最大宽度不超过正文。缩放使用 CSS，不拉伸或重采样原图。并排图片协调可见尺寸与间距；不要为了填满横向空间放大过头。
- 新的文章/章节标题沿用英语风格；标题前缀由用户决定，前缀与标题用空格分隔。保留论文正式名称，不擅自改现有标题或 slug。
- “先放本地目录”的推导保持独立文件，不因正文发布就自动接入页面；区分文件目录与文章目录。持续维护当前任务中已确认的选择。

## 导入与修改

- 先看工作区已有修改，接着做，不覆盖用户暂存内容。Lake 原始导出与原图保留不变；展示修订写入 manifest、覆盖文件或独立 Markdown。
- 需要导入 Lake、插入推导或替换算法时，读取 [仓库接入方式](references/repository-workflow.md)。现有文章和同系列文件是排版基准，不重新设计一套。
- **禁止额外计算哈希**：不执行 SHA256/MD5 等校验，不为文档、图片、公式或发布产物生成内容哈希，不恢复已删除的哈希流程。沿用现有不计算哈希的构建方式。

## 检查与发布

- 小改动：完成修改 → 一次构建 → 必要的局部检查 → 发布已授权的内容。仅在发现问题或新增修改后重跑相关检查，不反复做整站截图。
- **预览只检查桌面端**：默认不做手机端截图、移动视口、触控或响应式专项检查，不为此增加耗时或调整桌面排版；只有用户明确要求手机端时才检查。按正常桌面视口和实际正文列宽核对，不通过缩放浏览器掩盖溢出。
- 算法转写需逐步对照原图；公式改排版检查下标、编号、行数和实际宽度；图片检查比例与正文边界。全站样式改动可批量核对实际 CSS 数值，不必给每篇截图。
- 仅更新技能或维护说明、没有改页面源文件或构建逻辑时，校验技能与改动即可，不为此额外构建网站或打开预览。
- 在当前任务已授权发布时，直接提交本任务文件并推送，查看对应 Pages 构建和部署结果；成功后才说“已发布”。不为同一授权重复询问。仅本地整理或明确暂不发布时不推送相关内容；技能本身不授予新的外部操作权限。
- 用户重视速度：进度说明简短，必要时明确是本地构建、GitHub 排队还是部署在等待；不要用长解释代替修复。

## 持续维护

用户明确确认新的长期惯例时，同步更新此技能的相关条目，保留其适用范围。一次性图片尺寸或某个公式的分行要求留在文章配置里，不推广成全站规则。
