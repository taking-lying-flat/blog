# Technical Report II

## On the Design of Qwen3.8-Next Architecture: Evaluation, Efficiency, and Training Stability

**Qwen3.8-Flash-Next 是一个稀疏混合专家模型，总参数量为 125B，每个 token 激活 6B 参数，此外还包含存储于加速器之外、参数量为 51B 的 n-gram 嵌入表。其设计目标是以显著更低的计算预算，保持上一代旗舰模型 397B-A17B 的性能水平。**

- token 混合采用 Gated DeltaNet 与全局注意力按层交替的混合架构：循环层以线性计算成本将前缀压缩为固定大小的状态，同时每四层设置一个全注意力层，以保留有限状态记忆无法精确复现的 token 级直接检索能力。**在继续预训练阶段，这些全注意力层被替换为 Qwen Sparse Attention（QSA）。QSA 延续稀疏注意力技术路线，但采用基于压缩的轻量级索引器，以微块为粒度对上下文进行评分，从而降低长序列下索引过程本身的开销。**
- **残差流被拓宽为四个分支，并通过逐元素门控进行读取；将这一设计称为门控残差。拓宽残差流增加残差路径的容量，门控则决定如何使用这些容量，同时提供维持训练稳定性所需的重缩放。**
- 通过单个 n-gram 嵌入层，在主干网络之外进一步扩展容量。该层的嵌入表从主机内存中预取，使参数规模得以扩大，而每个 token 新增的浮点运算量与延迟均可忽略不计。

**损失与下游准确率的变化并不总是一致，观察到两个方向上的不一致现象。**

- 扩大 n-gram 词表规模会使损失单调下降，而下游准确率则趋于饱和；在固定参数预算下，损失最优配置与准确率最优配置也并不一致。相反，根据残差状态预测残差的读取与写入权重，仅带来较小的损失下降，却能明显改善基准表现。
- 将每个块限制为仅使用门控值最高的两个残差分支，几乎不会影响预训练损失，但随着训练进一步推进，性能会出现退化；**从全注意力层中移除位置编码，在预训练阶段未表现出可辨别的差异，却会影响后续阶段的生成质量。**

**分别评估训练、预填充和解码阶段的成本。**

- 在训练阶段，相较于 GPU 上的 Triton 基线实现，FlashQLA 的前向计算加速比达到 2–3 倍，反向计算加速比约为 2 倍。
- Muon 也引入相应的工程开销：其单位参数浮点运算量取决于矩阵形状，而非参数总量，因此需要依据估计的正交化成本，重新划分数据并行梯度缓冲区；此外，融合参数被拆分后，优化器更新步骤会分散为大量小型计算核，因此使用 CUDA Graph 捕获该更新步骤。将 Newton–Schulz 迭代次数设为 8，以优先获得压力条件下更高的稳定性。
- 在推理阶段，预填充的主要开销来自覆盖整个上下文的注意力计算。QSA 将键序列长度压缩至原来的 $`1/r`$，使索引器的计算开销从 $`O(n^2)`$ 降至 $`O(n^2/r)`$。解码阶段的主要开销则来自内存数据传输，因此 GDN 层采用固定大小的循环状态，GR 移除分支混合算子 $`H_{\mathrm{res}}`$，残差状态也支持以 FP8 格式存储。在上下文长度为 1M 时，从计算核层面衡量，QSA 相较于稠密注意力在预填充和解码阶段的加速比分别为 7.6 倍和 4.9 倍。

**Muon 应用于执行线性映射的二维权重矩阵；输入嵌入、n-gram 嵌入、输出头、MoE 路由器以及 GR 的低秩投影仍使用 AdamW，因为对这些参数进行正交化要么不切实际，要么无法带来收益。在正交化之前，先拆分融合参数，因为直接对拼接后的矩阵进行正交化，会混合互不相关的子块之间的奇异方向。**

- 新的架构与优化器也改变最优超参数，因此重新拟合 Qwen3.5 系列所使用的缩放定律。新的缩放定律预测，更大的批量大小和学习率更为合适。更大的批量大小提高大规模训练中的并行吞吐量，更大的学习率则改善收敛表现。
- 在训练初期逐步增大批量大小，最终效果并不优于从训练开始就采用目标批量大小，同时还会增加 18.8% 的优化器更新步数，因此未采用这一策略。

**通过压力测试验证训练稳定性：提高学习率，并在训练过程中保持学习率恒定，以便在中等模型规模下复现大规模训练中的不稳定现象。**

- 评判标准是：在相同压力条件下，新训练方案的稳定性至少应达到其所替代的上一代方案的水平。当学习率设为最优值的四倍时，前代架构频繁出现损失尖峰，而新方案在整个训练过程中均保持稳定。
- 仅以 GR 中的门控为变量进行的成对对照实验进一步证实，该门控是新方案相较于 Qwen3.5 架构获得更大稳定裕度的关键因素之一。得益于上述稳定性改进，Qwen3.8-Flash-Next 的全规模训练过程平稳推进，未出现任何损失尖峰或梯度范数异常波动，也未依赖 qk-clip 或 SwiGLU-clip 等显式裁剪方法。
